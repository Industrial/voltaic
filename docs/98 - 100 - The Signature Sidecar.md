# Plan 100 — The Signature Sidecar

Plan ID: `sidecar`
Depends on: 94, 99
Milestone: 16 — *the surface*
Status: `planned`

---

## 1. What this plan is

`<file>.vlt.sig`: one line per `pub` definition, carrying its inferred judgement.
Generated by the formatter, committed, diffed in review, and **it is the published
API**.

Plus the tools that make inference interrogable: `voltaic sig`, `--why`, `--semver`,
`--require-signatures`.

### 1.1 The problem it solves

Row 99 deletes every signature from the source. That creates three problems at once,
and they are not the same problem:

1. **A reader cannot see the API.** Answered by the LSP's inlay hints and by
   `voltaic sig`.
2. **A reviewer cannot see the API *change*.** Answered by the sidecar being
   committed: a change to a `pub` definition's inferred type is a one-line diff in the
   pull request.
3. **A downstream crate cannot compile against an inferred API without re-inferring
   it.** Answered by doc 86 §8.3 — the sidecar *is* what a downstream crate reads.

Problem 2 is the one that justifies committing a generated file, which is otherwise
something this repository has learned not to do.

### 1.2 Why committed, and why that is not plan 68's mistake

Plan 68 committed the generated `.rs` trees, plan 72 untracked them, and the account in
`AGENTS.md` is explicit about what went wrong: the generated Rust **was** the
previous-version compiler, so untracking it left a clean checkout with nothing to
build the compiler that would regenerate it. The fix was the seed blob — the same
previous-version compiler stored once instead of thirteen times.

The sidecar is not that shape, and the difference is worth stating because the
surface similarity is misleading:

| | Generated `.rs` trees (plan 68) | The sidecar |
|---|---|---|
| size | 18,013 lines across 13 crates | one line per `pub` definition |
| regenerable from source? | yes, but only by a compiler built from it | yes, by any compiler |
| is it load-bearing for the build? | **yes** — it was the bootstrap | **no** — a missing sidecar is regenerated |
| what is it for? | compiling | **reviewing** |

A missing or stale sidecar is `VLT0901` with the fix named — re-run the formatter. A
missing generated tree was an unbuildable repository. The sidecar is committed because
its *diff* is the deliverable, which is the one reason to commit a generated file that
survives scrutiny.

### 1.3 The format

Text, one definition per line, stable ordering, no timestamps:

```
# voltaic 2 signature sidecar — generated by `voltaic fmt`, do not edit
peek         self -> ?char                 @ shared
bump         self -> ?char                 @ unique ! mut self
eat          &str -> self -> bool          @ unique ! mut self
eat_while    (char -> bool) -> self -> Span @ unique ! mut self
```

Three properties, each load-bearing:

- **No timestamps, no hashes, no paths.** A generated file that changes when nothing
  changed is a file reviewers learn to skip.
- **Stable ordering** — source order, not hash order — so a diff is local to the
  definition that changed.
- **The full judgement**, `τ ! ε @ μ`, not just the type. A change from `shared` to
  `owned` is an API change and must appear.

### 1.4 `--require-signatures`, and the project dogfoods it

A crate may demand that every `pub` definition's inferred type be *written* as an
ascription, checked against inference, and refused if absent. Off by default.

The compiler's own crates **turn it on**, and that is the design's own answer to its
own risk: doc 88 §6.3 names API stability as the third of three risks, and the project
runs the strict mode on its published surface and the relaxed mode everywhere else. If
the relaxed mode were good enough for a published API, there would be no reason for the
flag to exist; if the strict mode were necessary everywhere, row 99 would not have
been worth doing.

Doc 88 §9 declines to decide whether the strict mode becomes the default in a later
generation, and the reason is given there: it is a policy question that wants a year of
use rather than an argument.

## 2. Preconditions

- Row 94 `done` — the judgement exists.
- Row 99 `done` — there is nothing in the source stating the API, so the sidecar has a
  job.
- `voltaic fmt` is canonical and idempotent (doc 87 §16), so the sidecar it writes is
  a function of the source alone.

---

## 3. Concrete proof this plan targets

Three demonstrations:

1. `crates/voltaic-lexer/vlt/cursor.vlt.sig` matching generation 1's twelve
   hand-written signatures, modulo the generation's spelling.
2. A deliberate narrowing — changing a `pub` function's body so its inferred parameter
   mode moves from `shared` to `unique` — producing a **one-line sidecar diff** and a
   `--semver` report calling it breaking.
3. A downstream crate compiling against an upstream crate's sidecar **without** the
   upstream source present, which is what proves doc 86 §8.3 rather than asserting it.

## 4. Leaves

### Leaf 1 — generation

`voltaic fmt` writes `<file>.vlt.sig`. Format per §1.3. A sidecar disagreeing with its
source is `VLT0901`.

### Leaf 2 — the sidecar as the published API

Cross-crate resolution reads sidecars, never upstream source. This is the leaf that
keeps separate compilation and per-crate caching working, and it is what adds
`.vlt.sig` files to the `dependency_sources` file group — the group `AGENTS.md`
records as the thing that actually makes moon's per-crate caching correct, since
`deps: ['^:check']` sets order rather than hash.

`crates/voltaic-cli/tests/moon_project_graph.rs` gains the assertion. Row 104 owns the
`dependency_sources` edit; this leaf owns the resolution behaviour that requires it.

### Leaf 3 — `voltaic sig` and `--why`

`voltaic sig <file>` prints judgements; `--json` for the LSP; `--why <name>` walks
row 94's provenance chain and names the use that forced each bound.

`--why` is not a convenience. Doc 86 §2 clause 1 admits a solver-determined lowering
*only if the choice can be printed*, so this leaf is where that clause is discharged
for modes and rows rather than only for types.

### Leaf 4 — `voltaic check --semver`

Compare a crate's sidecar against a previous version's and classify each change:
widening, narrowing, addition, removal. Narrowing and removal are breaking.

This is a capability **Rust does not have at all**, and it is the one place where
inferring the API is better than writing it: a written signature cannot be diffed
against the signature it replaced, because the old one is gone.

### Leaf 5 — `--require-signatures`

§1.4, plus turning it on for the compiler's own crates.

### Leaf 6 — `#[voltaic::opaque]`

The pressure valve (doc 87 §11): a `pub` definition whose inferred type is an
implementation detail may refuse to publish it, at the cost of being uncallable across
the crate boundary.

### Leaf 7 — LSP inlay hints

The sidecar's interactive half, and doc 88 §2 calls it the generation's biggest
user-visible win. Hints for every inferred judgement, hover showing `--why`, and a
code action that writes an inferred signature into the source as an ascription.

The code action matters more than it looks: it is the migration path for a user who
decides they want a signature after all, and it is what makes
`--require-signatures` adoptable incrementally rather than all at once.

---

## 5. Acceptance criteria

1. §3's three demonstrations hold, the third included — a downstream crate compiling
   with no upstream source present.
2. A sidecar is a pure function of its source: regenerating twice produces no diff,
   and regenerating on a different machine produces no diff. No timestamps, no paths,
   no hashes.
3. `VLT0901` fires on a stale sidecar and names the fix.
4. `--semver` correctly classifies all four change kinds, with a fixture each.
5. `--require-signatures` is on for every published crate in this workspace, and the
   gate proves it.
6. `.vlt.sig` is in `dependency_sources` for every crate, asserted by
   `moon_project_graph.rs`.
7. LSP inlay hints and the write-signature code action work in at least the two editor
   integrations `editors.rs` already covers.

---

## 6. Out of scope

- **Whether `--require-signatures` becomes the default.** Doc 88 §9.
- **A binary sidecar format.** Text, because the diff is the deliverable.
- **Publishing sidecars to crates.io as a separate artifact.** They are inside the
  crate, covered by the existing `include` keys that row 93 renamed.
- **Semver *enforcement*.** `--semver` reports; it does not refuse. A gate that
  refused would need to know the intended version bump, and that is a release
  decision — `docs/RELEASING.md` owns it.

Standing gate, plus the determinism check (§5.2), plus `--semver`'s four fixtures,

## 9. Decision log

| Decision | Why |
|---|---|
| Commit the sidecar | its diff is the deliverable; §1.2 distinguishes this from plan 68 |
| Text, source-ordered, no timestamps | a generated file that churns is a file reviewers skip |

| Sidecar is the published API | keeps separate compilation and per-crate caching intact |

## 10. Result

Partial. Leaf 1's **format, generation and gate** and leaf 4's **`--semver`** are
done. Leaves 2, 3 (beyond `--why`, which row 101 shipped), 5, 6 and 7 are open,
and §10.4 is the honest account of what leaf 1 still owes.

### 10.1 The format has no column alignment, and §1.3 is wrong about that

§1.3 draws the format with padded columns, then states as the second of three
load-bearing properties that ordering is stable *"so a diff is local to the
definition that changed"*. **Those two cannot both hold.** Padding is computed
from the longest name in the file, so adding one long name reflows every line
and the diff is the whole file — which is precisely the thing the property
forbids.

The property wins over the drawing. The format is single-space separated:

```
# voltaic 2 signature sidecar — generated, do not edit
new : &str -> Self @ src shared
pos : Cursor -> usize @ self shared
peek : Cursor -> Option<char> ! none @ self shared
bump : Cursor -> Option<char> ! none + mut self @ self unique
eat : &str -> Cursor -> bool @ s shared, self unique
eat_while : impl Fn(char) -> bool -> Cursor -> Span @ pred shared, self unique
```

That is `crates/voltaic-lexer/vlt/cursor.vlt` in full, generated, 14 published
definitions. `adding_a_long_name_does_not_reflow_the_other_lines` is the
assertion that keeps the format this way, and it exists because the padded
version is the one a future reader will find in this plan and reasonably try to
restore.

### 10.2 `--semver` catches a change Rust cannot see

§4 calls this a capability Rust does not have at all. The reason is exact: a
*written* signature cannot be diffed against the signature it replaced, because
the edit overwrote it. An inferred one can, because the previous one is a file.

Measured against the real `cursor.vlt`, with its recorded sidecar hand-altered:

```
$ voltaic sig crates/voltaic-lexer/vlt/cursor.vlt --semver old.sig
altered  eat
  was &str -> Cursor -> bool @ s shared, self shared
  now &str -> Cursor -> bool @ s shared, self unique
removed  removed_one
added    mark
error: 2 breaking change(s) of 3
```

The first row is the one that matters: **the type is byte-identical and the API
changed.** `eat` went from taking `&self` to `&mut self`, which breaks every
caller holding a shared borrow, and no type signature anywhere records it. This
is what putting `μ` in the sidecar buys, and §1.3's third property — *"the full
judgement, not just the type"* — is the one §1.3 got right.

Additions do not break; removals and alterations do; the exit status is the
classification, so this is usable from CI without parsing the output.

### 10.3 `--semver` takes one source, and refuses two

Two sources against one sidecar would silently compare only one of them.
`semver_refuses_more_than_one_source` pins the refusal, because the failure mode
is a passing check that compared the wrong file.

### 10.4 What leaf 1 still owes, and why it is a separate commit

§1.2 argues the sidecars should be **committed**, and they are not yet. Three
things have to land together for that to be safe rather than plan 68's mistake
again:

1. **`voltaic fmt` writes them.** Today `voltaic sig --emit` does. Until the
   format task regenerates them, 122 committed sidecars would go stale on the
   first `.vlt` edit with nothing to notice — a committed generated file with no
   gate is worse than no file.
2. **`VLT0901`** — a sidecar disagreeing with its source. The corpus gate
   asserts this for its own two cases; the tree-wide version is the diagnostic.
3. **The gate interactions.** `.gitignore` must *not* ignore them (it does not,
   checked), the manifests' `include` keys must carry them, and
   `dependency_sources` must list them — which §4 leaf 2 explicitly assigns to
   **row 104**, not here.

So the mechanism and its gate ship now, and the tree-wide emission ships with
`fmt` and `VLT0901`. Enumerating that rather than doing it halfway is the point:
the committed-sidecar decision is sound only with the regenerating gate beside
it, and committing the files first is the order that breaks.

### 10.6 Leaf 5 — `--require-signatures`, and what it found

`voltaic sig --require-signatures` refuses a published definition whose type is
only inferred, printing the inferred judgement so the fix can be pasted in.
`unwritten` is the check and it reads `Inferred.published`, which is
`FnDecl.visibility` — already in the AST and simply dropped on the way through
`one`.

§1.4 says the compiler's own crates turn it on. They pass: **every published
definition in all 122 files carries a written signature.** They did not when the
flag was first wired, and the three things in between are the result worth
keeping.

**It is vacuous in generation 1, and that is recorded as a test rather than a
note.** Generation 1's parser *requires* a signature — `export across p = p.x`
is a parse error, not an unsigned definition — so the demand cannot fail here.
`generation_1_cannot_express_an_unsigned_definition` asserts that the unsigned
form still fails to parse, so when row 99 wave 1 makes signatures optional the
test goes red and demands a real case. The flag is built now because the
*measurement* it enables is what wave 1 needs, not because it bites today.

### 10.7 The receiver defect: a gate that was true about a third less than it looked

The flag's first run reported **204 published definitions with no written
signature**, and every one of them was signed. `skip_layout : &mut self -> ()`
is fully annotated; `signature_type` returned `None` for it because it required a
written type on *every* parameter and `self` has none. So every method with a
receiver — 204 of them — read as unannotated.

The consequence for leaf 5 was a false positive. The consequence for **row 99
wave 1** was worse and quieter: that gate compares only definitions it believes
carry a written type, so it was comparing **809 of 1,139** and reporting
809/809. A true statement about a set a third smaller than it appeared to
describe, green the whole time, because 809 is not zero.

Fixed, the answer key is **229/229 on the examples and 910/910 on the compiler**.
`the_compared_set_has_not_shrunk` now puts a floor under both counts — a floor
rather than an exact count, so ordinary additions do not trip it while a
*narrowing* does.

Two smaller defects fell out of the same measurement:

- **`binder_of` did not strip a bare `mut `.** `mut self` is a by-value mutable
  receiver and four of the compiler's methods use it, so their binder read as
  `mut self`, the receiver was never recognised, and the mode column said
  `mut self shared`. It stripped `&` and `&mut ` and not `mut`.
- **`Self` had no owner to resolve against.** `offset_by : usize -> mut self -> Self`
  read as returning a type literally named `Self`. `Self` reaches a definition's
  type from two directions — the written return *and* the body's own constructor
  call — and which one a given definition uses is the author's choice, so
  expanding one side traded one disagreement for seventy-five. `Inferred` now
  carries its `owner` and `judged` / `declared` expand both sides. A class
  declaration's member has no owner and keeps `Self`, which is correct: there,
  `Self` means the implementing type and no concrete type exists yet.

The shape is the same one §10.5 and row 101 §10.9 record: **a gate keyed on a
predicate narrows silently when the predicate gets it wrong.** `report` already
refused a corpus with *no* written signatures, and that was not enough, because
the failure was never zero.

### 10.5 Measured: `main` calling an `io` function has an empty row

The `effects.vlt` corpus case records this:

```
announce : () ! io
main : ()
```

`main` calls `announce`, and row 95's implicit propagation says the caller's row
is the join of its callees'. It is not propagating through calls — `clause_row`
reads the body's own effects and stops. That is row 95 leaf 3's work and this is
the first place it shows as a concrete, blessed, wrong line rather than an
unimplemented leaf. The sidecar corpus will diff when it is fixed, which is what
the corpus is for.
